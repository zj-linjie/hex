# Hex 语音助手 PRD 草案

状态：v0.4，已获实施授权；复用小智官方回复音频。助手按用户最新确认改为右 Option。  
日期：2026-11-03（最新快捷键修订）。Hex 基线：`72231d18e579b2515ae0b17f8723444d02a88ee2`。

## 1. 目标与已确认需求

把 xiaozhi-voice 的助手能力接入 Hex：用独立快捷键说出指令，让本地 Mac 和已配置的 MCP 工具完成操作，并在 Hex 内看到结果。

用户已明确：

- 听写使用 Hex 本地识别；助手继续使用小智官方后台和原有智能体、MCP 桥接。
- Hex 接替 xiaozhi-voice 的交互入口；迁移时关闭旧语音客户端，保留执行工具所需的桥接。
- 在 Hex 面板内增加助手控制与设置。
- 目标绑定为左 Option 听写、右 Option 助手；两项均可在面板中更改。
- 按住快捷键时出现随声音变化的音浪。
- 执行结果显示文字；直接接收并播放小智官方返回的回复音频，保留播放开关。该链路在旧客户端已经实现，迁入 Hex 复用。
- 已授权实施、通过个人 fork PR 交付并更新本机应用；历史仅规划限制已覆盖。

用户最新选择覆盖 v0.1 中“本地识别后自行连接可配置模型/MCP”的建议。首版沿用小智助手的音频协议，因此助手音频发送给云端；本地听写不经过小智。本文其余未明确的默认值和实现方案仍为建议。

- Hex 当前的 `hex mcp` 是供外部读取会议记录的 MCP 服务，不负责本次小智后台到本地工具的桥接。

## 3. 用户体验

```ts
左 Option（听写，可更改）
└── 录音 → Hex 本地识别 → 原有文字处理 → 输入框

右 Option（助手，可更改）
└── 按住 → 音浪随麦克风输入变化
    └── 松开确认有效输入 → 音频送往小智 → 原有智能体识别、理解并按需调用现有 MCP 桥接
        ├── 完成 → 显示实际结果 → 可选语音回复
        ├── 需要补充/确认 → 显示问题 → 下一次助手输入继续
        └── 失败 → 指明失败阶段，保留可查看的结果
```

使用示例：

- “打开 Obsidian” → 调用打开应用工具，展示工具返回。
- “帮我找一下 Qwen 预热的笔记” → 搜索笔记并展示候选。
- “打开刚才第一篇” → 在当前助手会话内解析候选引用，再调用打开工具。
- “打开 B 站” → 网站工具；应用名和网站名不混用。
- 同一句“打开 Obsidian”从听写快捷键进入时，仍作为文字输入，不执行操作。

助手转写、回复和工具输出默认只出现在助手区域；不自动粘贴到前台输入框，也不覆盖 Paste Last 的听写结果。用户可主动复制。

## 4. 面板与启用流程（建议）

按 Hex 项目约定，新功能放入 Labs，默认关闭；开启后侧栏出现“语音助手”。首版只提供 macOS 能力，不承诺 Linux、Windows 同步可用。

```ts
Labs
└── 语音助手 [关闭 / 开启]
    └── 开启 → 侧栏出现“语音助手”
        ├── 就绪状态：麦克风 / 小智激活与会话连接
        ├── 听写与助手快捷键：左 Option / 右 Option，支持录制修改
        ├── 小智连接：原有助手身份接入、激活/连接/重连状态
        ├── MCP 说明：沿用官方后台绑定的桥接，提示前往原配置入口管理
        ├── 回复：文字结果、语音回复开关（小智原有 TTS）
        └── 当前会话：你的转写、小智回答、复制、取消/停止回复
```

面板中提供“开始说话 / 结束并发送”作为快捷键的可访问替代入口；原生权限缺失时显示具体恢复方式。

启用开关不等于连接就绪。未激活或会话未连接时显示具体状态；语音连接成功也不证明 MCP 桥接正常。首版不承诺在 Hex 内编辑小智后台的模型、人设或 MCP 绑定。

关闭功能后停止接受新的助手输入、停止本地播报，并尽力发送后台 abort。后台是否已执行工具并非 Hex 可保证，不能宣称云端任务或已发送操作已撤销。

## 5. 快捷键与录音规则

### 5.1 用户确认的绑定与切换

目标为左 Option 听写、右 Option 助手。此前左 Command 方案作废。迁移时关闭 xiaozhi-voice 的语音客户端，避免两套录音与热键入口并行；执行工具所需的 `xiaozhi-mcp/bridge.py` 保留运行。

前次只读检查的 Hex 配置仍是 `Option（任意一侧）`，本次未修改。实际实施时将其调整为用户确认的左 Option，并新增右 Option 助手绑定；其余设置保持原值。

关闭旧客户端解决外部程序竞争，Hex 内部仍需检查所有快捷键的侧别包含关系和组合冲突，包括 Paste Last、原始听写、第二听写与 Annotate。

右 Option 只在单独按住时形成有效助手输入，组合键出现时丢弃该次助手录音，不提交指令，并保留原组合键行为。左 Option 只触发本地听写，Command 键不触发默认助手绑定；Cmd+C、Cmd+V、Cmd+Tab 等照常。原生验收必须覆盖这些场景。

为保证上述行为，首版建议先本地缓冲助手音频，在松开且判定整次手势有效后，才经小智手动 listen 协议提交；发送节奏与后台兼容性须先验证，不能仅依靠已经上云后的 abort 保证组合键从未触发操作。此方案会影响助手首字延迟，验证后记录实际耗时。

### 5.2 首版输入语义（建议）

- 助手先支持 Hold：按住录音，松开提交。可更换单修饰键或 Hex 已支持的组合键。
- 单次录音由发起通道独占；听写和助手不同时录音，也不采用旧客户端“最后按下的键抢走麦克风”的规则。
- 助手录音中可取消，取消后不调用模型或工具。空录音、静音和误触不执行指令。
- 回复播放中再次按住助手键：停止当前本地播报，再开始新输入；旧回合迟到的文字/音频不得覆盖新回合。
- 工具正在执行时可停止本地等待和播报，并请求后台 abort；不保证中止云端工具执行。结果不明时不自动重发指令。
- 首版建议一个活动助手回合；新一轮输入与旧轮次通过会话/回合隔离，避免迟到音频混入。
- Toggle、双击锁定和免按键连续对话不列入首版必要范围。

## 6. 音浪与状态反馈

优先复用 Hex 当前 Dot scope 和 HUD 位置设置。录音动效以实际采样电平驱动，静音时回落，不能用循环动画伪装正在收到声音。

| 状态 | 用户可见反馈 |
| --- | --- |
| 录音中 | 随输入电平变化的音浪，带助手模式标识 |
| 识别中 | 明确的识别状态，不再展示为正在收音 |
| 思考/等待回复中 | 依照实际收到的后台事件显示；无工具执行事件时不虚构具体工具阶段 |
| 待补充/确认 | 显示后台问题，允许下一轮回答；可点击确认须有可靠协议支持后再实现 |
| 回复播放中 | 若提供扬声器音浪，必须由实际播放电平驱动；可停止 |
| 完成/失败/取消 | 状态短暂反馈，完整结果留在助手面板 |

HUD 保持不抢焦点。工具本身需要打开或聚焦应用时可以改变前台。录音音浪、等待动效、完成反馈必须能区分；减少动态效果时保留可读状态。

验收关注真实按键到首次可见反馈的延迟、音浪与声音的同步、松开后的状态切换；具体时延指标先测量基线再确定，不以转圈速度代表执行进度。

## 7. 小智官方后台与现有 MCP 执行链

### 7.1 职责与数据去向

```ts
左 Option → Hex 本地听写 → 输入框

右 Option → Hex 助手音频采集与编码
└── 小智官方设备 WebSocket → 原有助手智能体（ASR / LLM / TTS）
    ├── 转写与回答、音频 → Hex 助手面板与可选扬声器播放
    └── 智能体绑定的 MCP 接入点
        └── 本机 xiaozhi-mcp bridge → 原有工具服务 → Mac 操作
```

这是对旧客户端代码路径的确认，不代表当前运行中的 Hex 已实现该通道，也不代表本次已连接官方服务进行实时验证。首版迁入旧助手通道的协议适配，不新增 Hex 自建的模型工具循环。

本地听写保持本地识别，原有用户启用的后处理照旧。旧小智客户端在按住期间发送音频帧，松开结束输入；后台返回识别文本和回答。Hex 首版仍走同一助手音频协议，但为保护右 Option 组合键，建议按前述规则先本地缓冲再提交，发送时序需验证。不能把它描述为“助手也本地识别后只发文字”；若将来要支持此模式，须另行验证官方文本输入协议。

### 7.2 接入与迁移

- 复用旧客户端已实现的激活、设备身份、hello、手动 listen、音频编码/解码、重连和 abort 行为，遵循后台协商的音频格式。
- 优先让用户选择接入原有助手身份与智能体，保留旧身份文件用于回退；凭据安全导入，避免明文出现在日志、仓库或导出中。不创建或复用旧“听写智能体”通道。
- 切换时完整退出旧 xiaozhi-voice，避免同一助手身份同时建立两条客户端会话；Hex 成功接替前保留原客户端可回退。
- 保留现有 MCP bridge 与工具服务。关闭语音客户端和关闭工具桥接是两个动作，不能把整个 esp-xz 服务一起关掉。
- 首版直接沿用官方后台配置的人设、记忆、模型和 MCP 工具绑定。Hex 提供连接状态和会话交互，不承诺同步编辑后台配置或在客户端逐项禁用后台工具。
- 旧助手语音连通不等于工具桥接连通；须单独以受控的真实工具场景验收。未观察到 bridge 状态时显示“未验证”，不以 WebSocket 已连接冒充 MCP 正常。

### 7.3 能力边界与可观测性

用户希望保留的能力包括打开应用、打开网站、搜索/打开 Obsidian 笔记及现有 MCP 操作。实际上可调用哪些工具以小智智能体当前绑定和桥接配置为准，本次不擅自删减、扩展工具权限。首批验收建议使用打开应用和笔记查询，再逐项确认其他能力。

现有 bridge 代码聚合 Mac、音乐、家居、生图与点单工具；不能假定迁到 Hex 后这些能力自动变为不可用，也不能在 Hex 面板上画出实际没有生效的“工具禁用”开关。需要缩小范围时在原桥接/后台配置层明确实施。

旧客户端观察到的主要是转写、回答文本和 TTS 事件，不包含可依赖的逐工具结构化执行结果。因此首版展示“小智回答”，不把“回答说已完成”当作 Hex 独立验证成功，也不虚构工具名、参数、耗时和终态。若要展示工具审计明细，需另行增加桥接观察通道，并定义与当前回合的关联。

打开应用等操作的最终验收还需观察目标应用；后台回答、bridge 调用记录和实际效果分别记录。断线/超时后不自动重放可能已执行的助手指令。原有生图、点单的预览和明确确认流程继续保留，不绕过。

## 8. 文字结果、会话与语音回复

- 每回合显示：后台返回的识别文本、小智回答、连接/等待/播放状态；只展示协议实际提供的信息。工具执行明细属于后续桥接可观测性扩展。
- 沿用原有智能体的会话上下文来追问与选择候选。清空本地显示不等于清空云端记忆；“新会话”需有协议依据后定义。持久历史的保存期限另定。
- 日志默认记录阶段、工具名、耗时和错误类型；不默认记录完整口述、笔记正文、凭据或原始音频。
- 语音回复直接使用小智官方后台返回的音频，不增加语音来源选择。播放可关闭；关闭后仍显示完整文字结果。初始播放开关待定。
- 复用旧客户端已经实现的小智音频接收、解码与播放链路，按后台 hello 协商的格式播放，不重新合成回答。开关仅控制本地播放，不关闭文字回答事件。旧代码把回复文本事件与 `play_tts` 绑定，迁移时须拆开，避免关闭语音就丢失回答。
- 播放失败只影响语音反馈，保留已有文字回答，不重新提交操作。

## 9. 配置兼容与维护

- 新设置独立命名，不借用旧 `voice_action` / `edit_hotkey` 退役字段。
- 保留现有模型、麦克风、62 条词汇、个人脚本、听写处理和权限；实施时按用户已确认的左右修饰键方案修改相关快捷键。
- 运行时配置继续存于 Application Support，界面保存和实际运行状态分别验证。
- 迁移方案为关闭旧语音客户端并保留桥接；迁移只针对旧语音客户端；桥接保持运行，实施与安装证据见 voice-assistant-implementation.md。
- 首版沿用官方后台到原桥接的路径，不搬迁工具实现。助手协议适配来源、许可证与个人配置要区分，不把私有身份或资料提交到公开 fork。
- 后续代码在个人 fork 功能分支开发，通过 PR 合入 `dev`；更新受影响的 feature map。涉及窗口绘制的修改按仓库要求更新并逐张检查 Linux goldens。

## 11. 后续拆分与待定项

建议开发顺序：
