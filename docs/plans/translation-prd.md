# Hex 翻译 PRD

状态：v0.5，macOS 雏形源码与自动化检查已完成，准备通过个人 fork 分支 `codex/translation` 的 PR 交付。用户要求不合并、不更新本机安装；2026-11-09 明确结束 Linux 测试与 golden 收集。本稿不将尚未执行的原生端到端验证记为通过。
日期：2026-11-09。行为地图：[translation.md](../features/translation.md)。

## 1. 要解决的问题

阅读英文时，把一个单词或短句粘贴进 Hex，快速看懂中文意思，并听到英文读音。单词结果还要显示音标，尽量像一张简洁的词典卡片。

这是一项独立功能，有自己的页面、快捷键和小窗口。沿用 Hex 的 Rune 界面和设置方式。

任务单：[Linear ZJ-31](https://linear.app/zjlinjie/issue/ZJ-31/hexmacos-本地优先英译中音标朗读与独立快捷键窗口)。用户补充明确：页面原型必须能在 Rune + rune-kit + 现有 Hex 主题中实现；这项约束指 UI 框架，不是新增 REST 架构要求。

视觉方案：[imagegen 原型 v1](../designs/translation/README.md)，包含单词主页面和短句独立小窗；已附到 Linear。示例数据与图片不构成原生运行证明。源码已有 Labs 开关、Rune 页与独立小窗、本地引擎、兼容 API 预览发送，以及 `8fb409e` 审查缺陷的当前修复（`AudioHolds`、异步 `bump` 唤醒、听写未就绪时的独立快捷键 tap、纯 `engine_config` 测试、查询框辅助功能名称、俄语助手词条）。最终快捷键配对和三文件兼容修正已通过针对性复核。Linux 测试与 golden 按用户要求跳过；原生窗口、真实 IME、物理快捷键、朗读、完整词典安装、离线系统翻译和云端发送均未记为通过。

### 已确认

- 只考虑 macOS。
- 第一版只做英文 → 简体中文，覆盖单词和短句。
- 支持手动输入、复制后粘贴。
- 单词要有音标、中文释义和可点击的朗读；短句要有译文和英文朗读。
- 本地优先；本地失败后，由用户手动选择联网翻译。
- 全局快捷键唤出独立的小翻译窗口；Hex 主界面也保留翻译入口。
- 快捷键采用 `Control + Option + T`，开发时检查冲突，支持更改。
- 联网翻译复用 Hex 现有兼容 API 的服务和模型，不使用 OpenCode；每次由用户显式发送。
- 遵循 Hex 现有界面规范，先完成 PRD，再推进功能雏形。

以下默认值、资源选择、尺寸和实现顺序是本稿建议，不代表用户已经逐项确认。

## 2. 第一版范围

### 必须完成

1. Labs 增加“翻译”，默认关闭；开启后侧栏出现“翻译”。
2. 单词查询：词头、音标、按可用数据组织的词性及中文释义、英文朗读、复制释义。
3. 短句翻译：原文、中文译文、英文整句朗读、复制译文。
4. 一个独立的翻译小窗口，通过全局快捷键或翻译页中的“打开小窗口”唤出。
5. 可录制修改的独立快捷键，与 Hex 现有快捷键检查冲突。
6. 显示结果来源；本地不可用时提供明确恢复入口和手动联网入口。
7. 文本输入、结果复制、音标显示和状态反馈符合键盘及辅助功能规范。

中译英、多语种、划词取词、OCR、自动读取选区或剪贴板、整篇文档翻译、生词本、背单词、持久查询历史、真人发音音频库、音频文件导出。

## 3. 入口和窗口

```ts
Hex › Labs › Output › 翻译 [默认关闭]                 // TR-01
└── 开启
    ├── 侧栏出现“翻译” → 主窗口翻译页
    │   ├── 输入、查询、朗读、复制
    │   ├── 打开小窗口
    │   └── 设置：快捷键、发音、资源状态、联网服务
    └── 已绑定的全局快捷键 → 独立翻译小窗口           // TR-02
        └── 输入框获得焦点 → 粘贴 → 查询

关闭 Labs 功能
└── 隐藏入口和小窗口，停用快捷键，取消等待，停止朗读
    └── 保存的设置保留；已发出的网络请求不保证能撤回
```

建议归入现有 Output 分组，audience 为 `Everyone`，仅 macOS 提供能力。关闭时不启动查询、翻译或语音工作。

### 独立小窗口

- 用同一 Hex 进程中的 Rune 窗口实现；输入和结果界面使用 `rune-kit` 与 Hex 的主题、间距、字体、圆角。
- 初始尺寸建议约 540 × 460 pt，可随结果向下展开，最大高度受当前屏幕可用区域约束；长结果在内部滚动。
- 首次打开位于当前活动屏幕的可用区域；再次打开尽量沿用仍在屏幕内的位置。
- 快捷键可主动激活小窗口并聚焦输入框；这是可输入窗口，与不抢焦点的听写 HUD 不同。
- 已打开时再次按快捷键，前置并聚焦同一个窗口，不创建副本，不自动提交。
- Esc 优先关闭当前弹层；没有弹层时隐藏小窗口并停止该窗口的朗读。红色关闭按钮同样隐藏窗口，Hex 继续运行。
- 用户切到其他应用时不自动关闭或抢回焦点；不承诺系统禁止的跨 Space 或全屏行为，原生验证后记录实际边界。
- 关闭小窗口不关闭主窗口。关闭整个 Hex 时，查询、语音和窗口随进程有序结束。

### 主窗口翻译页

与小窗口复用查询内容和结果组件，附加设置区域。同一进程只有一个当前查询；在任一界面提交会同步另一界面的结果。两个界面同时打开时，文字更新不移动另一界面的焦点或光标。

首版不落盘保存查询文本。隐藏后本次查询可留在内存中供再次查看；显式清空、关闭 Labs 或退出 Hex 时清除。

## 5. 查询行为

### 输入和提交（TR-03）

- 支持标准 Cmd+V，也提供“粘贴”按钮。只有这些显式动作读取一次剪贴板；打开窗口不会读取，后台不监控。
- 接受纯文本，丢弃富文本格式。去掉首尾空白，保留句内换行、大小写和标点。
- 输入框内 Enter 提交，Shift+Enter 换行；中文输入法组词期间 Enter 只确认组词。提交处理限定在输入框，不给整页设置常驻的默认按钮。
- 空输入禁止提交。建议上限 1,000 个 Unicode 字符，超限说明原因，不截断后悄悄翻译。
- 编辑后立即使旧请求失效，旧结果不再作为当前输入的结果展示；只有显式提交才开始新查询。
- 只有一个当前请求。重复提交相同内容不重复排队；新查询、取消、关闭功能后，旧回包不得覆盖当前状态。
- 输入不是可识别的英文时提示首版支持范围，不自动换方向或发到云端。夹有技术缩写、数字、产品名的英文短句正常处理。

### 单词（TR-04）

优先按完整输入查本地词典，包括词典已有的多词词条。查不到完整词条时，含词间空白的输入走短句翻译；单个词先尝试有据可查的变形映射，再尝试本地机器翻译。

单词结果按来源显示：

- 查询词和实际命中的词头不同，要同时标出，例如“gave → give”；变形查询不能把词根的音标标成输入词的读音。
- 释义按真实词典的词性组织；源数据无法可靠拆分时保留原有释义结构。
- 有音标显示音标；无音标显示“暂无音标”。不使用模型猜出的字符串充当词典音标。
- 英美音标和读音分别来自各自资源，不以选择英式声音推导出英式音标。
- 查不到词典但机器翻译成功，标明“机器翻译”，不伪装成词典释义。
- 常用词样本必须具备音标才能通过核心验收；“暂无音标”是长尾缺项的恢复行为，不可替代这一要求。

### 短句（TR-05）

显示完整原文和中文译文，保留基本段落与标点。短句不显示整句音标，也不自动展开逐词解释。英文整句可朗读，译文可复制；首版不要求中文译文朗读。

## 6. 朗读（TR-06）

- 首选系统 `AVSpeechSynthesizer` 与设备上可用的英文 `AVSpeechSynthesisVoice`，不走小智音频或云端 TTS。[Apple 语音合成文档](https://developer.apple.com/documentation/avfaudio/speech-synthesis)
- 用 `speechVoices()` 核实可用声音；英式、美式标签绑定真实的 `en-GB`、`en-US` 资源，不把其他口音冒充成这两种。[声音枚举接口](https://developer.apple.com/documentation/avfaudio/avspeechsynthesisvoice/speechvoices())
- 建议默认不自动播放，点击后才朗读。提供正常、慢速两档；慢速指合成语速参数，不承诺固定的音频倍速。
- 同一时间只有一个翻译朗读。重复点击正在播放的按钮可停止；切换口音或查询先停止旧朗读，再播放新内容。
- 朗读内容是按钮所属的词头或原文，不自动读全部释义。按钮名称明确“朗读英式发音”“朗读原文”“停止朗读”。
- 声音缺失时给出系统声音设置指引；不自动下载、不静默切换云端声音。用户主动下载系统声音后可重新检查。
- 听写、助手或会议正在录音时不开始朗读；已有朗读遇到这些录音开始时停止。翻译不打开麦克风，不改变录音环境或听写结果。
- 当前设备声音能否完全断网合成必须实测；本稿尚未证明这一点。

## 7. 本地资源和联网兜底

### 首选组合

| 能力 | 首选资源 | 边界及缺失时的处理 |
| --- | --- | --- |
| 中文释义、词性、音标 | 本地英汉词典，钉扎 ECDICT（用户安装） | 固定 git/校验和；字段可能缺失，英美音标未必分别提供；真实安装待验证 |
| 短句翻译 | Apple Translation 的已安装英中语言资源 | 就绪检查后再用；缺失时指导用户准备资源，或手动联网 |
| 单词与短句朗读 | 系统已安装英文声音 | 核实声音、地区和实际离线可用性 |
| 联网翻译 | Hex 现有兼容 API 的服务和模型 | 不使用 OpenCode；复用已配置的服务、模型和凭据机制，每次显式发送 |

ECDICT 说明提供 `phonetic`、中文 `translation`、词性及变形数据；音标以英式为主，例句和音频字段不是可依赖的已完成能力。它是已钉扎的词典来源，不能承诺完整复刻截图或每个词都有音标。来源、声明和钉扎体积见上文与 `THIRD_PARTY_NOTICES.md`。[字段说明](https://github.com/skywind3000/ECDICT#readme)

系统 Dictionary Services 的释义文本可作技术评估，但本稿不假设它能稳定提供结构化英汉释义、双口音音标和例句。不能把系统“查找”弹层当成 Hex 自己的翻译界面。

### 系统翻译的版本边界（TR-07）

Apple 文档说明 TranslationSession 使用设备上的翻译模型；安装资源可在应用间共享。[Apple Translation 说明](https://developer.apple.com/videos/play/wwdc2024/10117/)

本次实际检查到开发机为 macOS 27.2；已安装 SDK 声明：TranslationSession 从 macOS 15 提供，直接创建 `TranslationSession(installedSource:target:)` 从 macOS 26 提供；显式选择策略从 macOS 26.4 提供。这只是 API 可用性，不证明机器已有英中语言资源或能够完成离线翻译。

- 雏形优先在这台 Mac 上接入无 UI 的已安装语言会话，Rust 通过小型 Swift 桥调用；Rune 继续拥有全部翻译界面。[无 UI 会话](https://developer.apple.com/documentation/translation/translationsession)
- macOS 26.4+ 建议显式选择 `lowLatency`，就绪检查与实际翻译使用同一策略，避免随 SDK 默认策略变化而换用其他模型。更早系统用相应版本可用的接口，单独验证。
- 直接创建的会话无法请求下载。资源未安装时不能用这个接口假装完成准备；首版引导到系统语言资源管理，重新检查后再查询。[下载限制](https://developer.apple.com/documentation/translation/translationsession/canrequestdownloads)
- 框架的应用内准备流程涉及 SwiftUI 的 `translationTask` 和 `prepareTranslation()`；本稿不以隐藏 SwiftUI 界面规避 Rune 约束，也不承诺已经接通该流程。[准备接口](https://developer.apple.com/documentation/translation/translationsession/preparetranslation())
- 不提高整个 Hex 的 macOS 最低版本。macOS 15 的系统翻译接入仍需验证；未实现时显示具体能力缺失，词典和朗读按实际能力可用，联网由用户手动选择。
- 首版不为句子另装大型生成模型；是否需要其他本地翻译引擎，等系统路径实测后再决定。

### 资源准备

词典由用户点击“安装词典”后才下载；支持失败后重试、原子安装和校验。钉扎 ECDICT git `39cfb9672c0906b63569e0453c2e6abfb9ab182a`：`ecdict.csv` 66009548 字节 sha256 `d1ecbdf9ee2b920afb6b430ca6b6bb9f559588cf0dff86e04bd255f9390843cc`，`lemma.en.txt` 2318694 字节 sha256 `e255b097404e3e0052060e2ddf6e15a1414f577071d63d51d2ca0ce9dacee0fc`，落到 Application Support/hex/translation。不用 `ecdict.mini.csv`。真实下载与条目加载仍待验证。

系统翻译语言包和系统声音由系统管理；Hex 提供指引和重新检查，不能随关闭 Labs 删除共享系统资源。词典不按每次查询重复加载，重工作不进入 UI 或音频线程；启动 Hex 不预热本功能。

### 手动联网（TR-08）

1. 本地词典或系统翻译失败后，保留原因和输入，提供“联网翻译…”。
2. 展示本次使用的服务、模型、当前待发送文本；明确这是联网翻译。
3. 用户点击发送后才请求。没有配置时先进入服务设置；配置完成不自动补发。
4. 请求只含当前查询文本、英译中任务与必要的输出格式；不附带剪贴板其他内容、听写历史、助手会话、前台应用或文件。
5. 结果明确标注联网来源；单词可展示联网译义，但模型生成的音标不得充当已核实的词典数据。朗读仍优先使用本地声音。
6. 超时、取消或结果不明时不自动重发，不切到其他供应商；回到可重试状态。

用户已选择复用 Hex 现有兼容 API 的服务和模型，明确排除 OpenCode 翻译。复用现有配置及私有凭据读取机制，但翻译请求独立构造，不运行听写后处理的提示词、转换或自动执行策略，也不要求 `labs.compatible_rewrite` 或 `compatible.selected`。页面显示实际使用的服务和模型；未配置或配置失效时引导到现有兼容 API 设置，配置完成后仍需重新点击发送。文档工作不读取密钥、不发起模型调用。

本地成功但用户不满意时也可在结果的次级菜单选择“联网重译…”，仍经过同一显式发送流程。未选择联网时，查询不会发到外部服务；资源下载与系统可能存在的使用指标应另行描述，不能宣称 Hex 整个进程零网络活动。

## 8. 快捷键（TR-09）

- 绑定名称：“打开翻译”。用户已选择 `Control + Option + T`，可录制更改；开发时检查冲突，不能覆盖用户现有绑定。
- 只在功能开启且绑定有效时响应，采用按下一次唤出；不使用 Hold、双击锁定或录音状态机。
- 复用 Hex 的快捷键录制、侧别匹配和冲突检查，加入独立的翻译槽位。与听写、助手、Paste Last、原始/第二听写、Annotate、截图等活动绑定双向检查。
- 发生 Hex 内部冲突时拒绝保存并说明冲突项；外部应用或系统占用不保证能全部检测，原生测试需验证候选键。
- 录制绑定期间按现有机制暂停全局匹配；Esc 取消，保留旧绑定。
- 不因唤出窗口而读取剪贴板、开始翻译或朗读；原有 Cmd+C、Cmd+V 保持正常。
- 全局热键能力与录音监听的启动门槛要分开核查：有快捷键所需的系统权限即可唤出，不因听写模型未安装或麦克风权限缺失而阻止用户点击进入翻译。

## 9. 状态与恢复

```ts
空闲 → 输入 → 提交
├── 资源检查 → 本地查询/翻译中 → 成功
│   ├── 词典完整 → 音标 + 释义 + 可用朗读
│   └── 部分成功 → 保留可用字段，说明缺失项
├── 资源缺失/不支持/失败 → 保留输入 + 具体恢复入口
│   └── 用户选择联网 → 确认服务和文本 → 发送 → 成功/失败
└── 编辑/新提交/取消/关闭 Labs → 旧请求失效
```

词典结果与朗读分别可用：例如声音缺失不隐藏释义，音标缺失不禁止朗读。错误信息区分词典未准备、未收录、语言资源未安装、系统版本不支持、声音缺失和网络失败。结果过期或任务超时不得永久显示“处理中”。

建议本地词典热查询目标 <150 ms、已准备的短句翻译目标 <3 s；这些是待测体验目标。耗时超过 300 ms 显示处理状态，本地翻译设置有界等待（建议 30 s），联网设置独立截止时间并允许取消；不能在 UI 线程等待。
